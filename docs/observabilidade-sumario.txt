ARQUITETURA
===========

Observer pattern thread-safe:

  [Broker Thread 1]     [Broker Thread N]     [User Handler Thread]
        |                     |                      |
        +-----NotifyEvent-----+------+
                                     |
                         [Copy list of handlers, release lock]
                                     |
                        [Call each handler with Event]
                                     |
                   [Each handler runs async, independently]

Garantias:
- Ordem de eventos por thread de origem (FIFO dentro da conexão)
- Zero overhead quando sem subscribers
- Handler exception isolada (não afeta outros handlers ou engine)
- Thread-safe: Subscribe/Unsubscribe podem vir de qualquer thread

EVENTOS CRÍTICOS JÁ DISPARADOS
===============================

Fase 4.1: implementação do framework de observabilidade
Fases posteriores: adição de NotifyEvent nos 5 pontos críticos:

1. TAMQPServerConnection.ProcessBasicPublish
   -> seMessagePublished
   -> seMessagePublishRejected (se fila cheia ou sem rota)

2. TAMQPServerQueue.Enqueue
   -> seMessageEnqueued
   -> seMessageDropped (se teto excedido)

3. TAMQPServerQueue.TryDeliver
   -> seMessageDelivered
   -> seMessageExpired (se TTL venceu)
   -> seMessageDeadLettered (se vai para DLX)

4. TAMQPServerConnection.ProcessBasicAck
   -> seMessageAcked
   -> seMessageNacked
   -> seMessageRejected

5. TAMQPMonitorThread / TAMQPJournal
   -> seJournalFlushed (Fase 4)
   -> seConnectionClosed
   -> seConsumerRegistered / Cancelled

PADRÕES DE USO
==============

1. AUDITORIA (BD ou arquivo)
   - seMessagePublished → INSERT INTO audit_log
   - seMessageDelivered → marca consumo
   - seMessageAcked → marca confirmação
   - Decisão: abastecida não pode ser usada por outro PDV

2. DEBUGGING
   - Salvar último N eventos em ring buffer
   - Na falha, despejar buffer no log

3. MÉTRICAS EM TEMPO REAL
   - seMessagePublished → Inc(PublishCount), Add(MessageSize)
   - seMessageAcked → Inc(AckCount)
   - seMessageNacked → Inc(NackCount)

4. ALERTAS
   - seMessageExpired → enviar alerta (TTL muito curto?)
   - seMessageDropped → enviar alerta (fila pequena demais?)
   - seConnectionClosed abruptamente → investigar PDV

5. RASTREAMENTO DE LATÊNCIA
   - Guardar TickMs de seMessagePublished
   - Comparar com TickMs de seMessageDelivered
   - Calcular publish -> deliver latency

EXEMPLO MÍNIMO
==============

procedure TMyApp.OnEvent(const E: TAMQPServerEvent);
begin
  WriteLn(Format('%s: %s user=%s',
    [DateTimeToStr(E.WallTime),
     GetEnumName(TypeInfo(TAMQPServerEventType), Ord(E.EventType)),
     E.Username]));
end;

procedure TMyApp.Start;
begin
  FServer := TAMQPServer.Create;
  FServer.Subscribe(OnEvent);
  FServer.Start;
end;
